# Responsive

Components have no media queries. The theme's `scale.css` sets one unitless token, `--ds-scale`, and applies it once to the root font size. Every `rem` on the page follows, the library's and yours. Mobile first: the base is the smallest, `min-width` queries in `rem` raise it.

## Breakpoints

Resize the window. The active row is highlighted.

<BreakpointTable client:load rows={ROWS} />

Below 320px the base step (`0.875`) applies. Media queries in `rem` ignore the root font size, so each breakpoint keeps its pixel meaning.

## Default setup

`@repo/uih/themes/aurora/scale.css`, part of `index.css`. Nothing to configure. Skip the file to keep a fixed size, or replace the steps:

```css
:where(:root) { --ds-scale: 0.875; }

@media (min-width: 30rem) { :where(:root) { --ds-scale: 0.9375; } }
@media (min-width: 48rem) { :where(:root) { --ds-scale: 1; } }
@media (min-width: 80rem) { :where(:root) { --ds-scale: 1.0625; } }
@media (min-width: 120rem) { :where(:root) { --ds-scale: 1.125; } }

:where(html) { font-size: calc(100% * var(--ds-scale)); }
```

## Change the steps

Your CSS wins over the theme (the theme is layered, specificity 0). Own one more breakpoint:

```css
@media (min-width: 64rem) {
  :root { --ds-scale: 1.03125; }
}
```

Or take over the root size completely:

```css
html { font-size: 100%; }
```

## Dense area

`--ds-scale` is root only. For one area use `--ds-density`, a multiplier on type and space (default `1`). Tokens are computed where declared, so the area needs `data-ds-theme`:

```html
<div data-ds-theme style="--ds-density: 0.8">...</div>
```
