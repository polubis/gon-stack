# Time

## DoD

**[user]** can plan, review, complete and remove **[task]** entries on day, week, month and year views backed by their account data.

### Task Retrieval

1. The application provides the **[task]** entries of the signed-in **[user]** that fall into the viewed period.
2. **[user]** can view a day, a week (Monday to Sunday), a month or a year.
3. **[user]** can move to the previous or next period and the viewed period is kept in the address.
4. Period views open on the current period when none is chosen.
5. Day view lists timed **[task]** entries by hour, then entries without an hour.
6. Week view groups **[task]** entries by day, timed ones by hour.
7. Month view marks each day with a dot in the **[task_category]** colour per **[task]**.
8. Year view shows the **[task]** count of each month.
9. Today and the current hour are highlighted.

### Task Creation

1. **[user]** can create a **[task]**.
2. A **[task]** has a name of 1 to 40 characters, a day, a **[task_category]** and a **[task_priority]**.
3. A **[task]** is pinned to an hour or lasts the whole day.
4. A new **[task]** defaults to the viewed day, medium **[task_priority]** and the first **[task_category]**.

### Task Maintenance

1. **[user]** can edit name, day, hour, **[task_category]** and **[task_priority]** of a **[task]**.
2. **[user]** can mark a **[task]** done or not done.
3. **[user]** can delete a **[task]** after confirming.

### Task Category And Priority

1. **[user]** can list and create **[task_category]** entries with a name, colour and icon.
2. **[user]** can list and create **[task_priority]** entries with a name and a value from 1 to 10.
3. Every account starts with the categories work, home, health, learn and rest.
4. Every account starts with the priorities low (2), medium (5) and high (9).
5. A **[task_category]** or **[task_priority]** in use by a **[task]** cannot be removed. <!-- auto: removal is not offered -->

### Feedback

1. While data loads for the first time, a skeleton mimicking the view is shown.
2. While data reloads after a period change, the previous data stays visible under a loading banner.
3. A view without **[task]** entries shows an empty state with an add action; with a period it names the period.
4. Create, edit, complete and delete apply instantly and roll back with an error toast (retry, close) when the server rejects them.
5. A failed load shows an error with retry and back actions.
6. Add, task, category and priority forms open as stacked modals kept in the address.
