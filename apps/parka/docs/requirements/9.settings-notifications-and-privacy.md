# Settings, Notifications & Privacy

## DoD

**[user]** can manage account and security settings, receive and configure **[notification]** alerts, export personal data, and access privacy and AI transparency disclosures.

### Account Management

1. **[user]** can manage profile information.
2. **[user]** can manage security settings.

### Profile Avatar

1. **[user]** can upload an image as their **[profile_avatar]**.
2. **[profile_avatar]** is accepted only when it is a real image (JPEG, PNG, WebP or GIF) of at most 10 MB; the check runs on both client and server, and the server verifies the file content, not the declared type.
3. The server stores the image as square WebP variants of 32, 64, 128 and 256 pixels, each at quality 40, scaled from the original.
4. **[user]** sees the **[profile_avatar]** in settings in place of the default profile icon; without one the default icon stays.
5. Upload is the only way to change the **[profile_avatar]**; **[user]** sees and replaces only their own.

### Device Avatars

1. **[user]** sees the **[device]** list of their **[expense]** records in settings.
2. **[user]** can choose a **[device_avatar]** for each **[device]** from a fixed set.
3. **[user]** can reset a **[device]** to the default icon of its type.
4. Chosen **[device_avatar]** is stored per account and applies to all **[expense]** records of that **[device]**, past and future.
5. **[user]** sees only their own **[device]** entries.

### Device Photos

1. **[user]** can upload an image as the **[device_photo]** of each **[device]**.
2. **[device_photo]** follows the **[profile_avatar]** rules: real image (JPEG, PNG, WebP or GIF) of at most 10 MB, checked on client and server; stored as square WebP variants of 32, 64, 128 and 256 pixels.
3. **[device_photo]** is stored per account and applies to all **[expense]** records of that **[device]**, past and future.
4. **[device_photo]** takes precedence over **[device_avatar]**; without one the **[device_avatar]** or type icon stays.
5. **[user]** sees a preview at once; a failed upload restores the previous picture and reports the error with a retry option.
6. **[user]** uploads and sees only photos of their own **[device]** entries.

### Device Recognition

1. Each **[device]** gets a **[device_color]** derived from its id; two identical phones differ without any choice by **[user]**.
2. **[device_details]** are collected by the browser without any model-name table: on Android Chromium the raw model code and OS version, elsewhere browser, OS and screen resolution.
3. Without a custom name the **[device_label]** is built from **[device_details]**, for example `SM-S918B · Android 14 · Chrome`; the technical name stays as secondary text.
4. **[user]** can set an optional custom name for each **[device]**; clearing it restores the built name.
5. Custom name applies to all **[expense]** records of that **[device]**, shown in lists and details.
6. Each **[device]** shows a short id suffix as secondary text.
7. Settings mark the **[device]** of the current browser as "To urządzenie".
8. **[user]** can press "Rozpoznaj to urządzenie"; the current **[device]** entry is highlighted, scrolled into view, focused and announced to screen readers. Highlight is static when reduced motion is preferred.
9. Without an **[expense]** from the current browser there is no entry to identify; the action is unavailable.

### Notifications

1. The application delivers **[notification]** entries to the signed-in **[user]**.
2. **[notification]** types include limit warnings, **[receipt]** processing confirmations, and **[spending_limit]** alerts.
3. **[user]** can configure **[notification]** delivery preferences.

### Data Export

1. **[user]** can export their financial data as **[data_export]**.
2. **[data_export]** is available in CSV format.
3. **[data_export]** is available in PDF format.

### Privacy & GDPR

1. **[user]** can access privacy and GDPR disclosures.
2. Privacy disclosures state that **[user]** data is stored in the EU and encrypted.
3. **[user]** can manage their personal data under GDPR rights.

### AI Transparency

1. **[user]** can access disclosures about **[ai_receipt_analysis]**.
2. AI disclosures explain how **[receipt]** data is analyzed.
3. AI disclosures explain how spending anomalies are detected.
