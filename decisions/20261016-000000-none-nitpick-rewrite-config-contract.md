summary: Rewrite config contract to typed rules, agents and refs
why: Typed ids and one doc field catch ref typos at compile time while generated rules output stays identical

- `config()` takes `settings`, `entry`, `rules` (group is the key), `agents`, `refs` and `output`
  - Ids come from keys, `ref` is the union of rule and agent ids (also with all-callback agents), `file` and `insert` take the union of `refs` keys
  - `instruction`, `check`, `group`, `id` replaced by `doc`, `run`, key names; `run` only on rules, needs `fix`
- `doc` is a string, `{ file }` or a callback on rules, agents and entry; callbacks get `ref`, `file` and `insert(key)`
  - `insert` lowers headings by one level (fenced code untouched) so pasted files nest under the current section
  - `file` links a `refs` file, `insert` inlines its content at generation time; missing file is a verification problem (exit 3)
- Old normalizer and internal model removed: `docs.ts` and `run.ts` work directly on the config shape, ungrouped rules, `docs.header/intro`, `knowledge.dir` and rules arrays are gone
- No `groups` option: its `keyof R` inference site widened `ref` to `string`; group file title comes from the group key (`unit-testing` -> `Unit Testing`)
- Duplicate unit ids throw in `config()` and are reported by `buildDocs`
- Agents render to `<path>/agents/<id>.md` with optional `frontmatter`, listed under `## Agent files`
  - `coord`, `worker`, `doctor` migrated into `.nitpick/config.ts`, originals in `.claude/agents` kept
  - `coord` doc uses `ref` for `worker`, `doctor`, `testing-pyramid` and `insert('aodi-framework')`
    - built-in reference from `@repo/nitpick/rules/aodi-framework`, attached via `refs` like built-in rules
    - only `agents/coord.md` output changes
  - `repo-config.test.ts` builds real `.nitpick/config.ts`; vitest alias maps `@repo/nitpick/*` to `src/*.ts`, no `dist` needed
- Ready-made rules export units without id and group; repo config migrated, rules, references and `.mcp.json` output byte-identical
- Root docs get a `## Reference files` section listing every `refs` file
  - AODI legend is a bare tag table (`aodi-framework.md`), single source for `AGENTS.md` and `insert`, printed under `## Rule files`
  - `entry` ctx has no `aodi`
- Repo `entry` is a plain title, the "Generated by nitpick" line is dropped
