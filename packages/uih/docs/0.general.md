# General Requirements

## DoD

Headless library with a single default theme that is optionally attached via a separate file. The theme may be included in all consuming applications, with live refresh support to avoid constant rebuilds during development.

All styling should be implemented so that styles can be overridden at JavaScript runtime. Include a separate example editor application that displays the default theme and allows editing it using only components from the library (covering the full documentation).

Components should have consistent APIs. For example:

```tsx
import type { ComponentProps } from 'react';

export type ButtonVariant = 'primary' | 'secondary' | 'ghost' | 'danger';

export type ButtonRootProps = Omit<ComponentProps<'button'>, 'type'> &
  { variant?: ButtonVariant } & {
    type?: 'button' | 'submit' | 'reset';
  };

const Root = ({
  variant = 'primary',
  type = 'button',
  ref,
  ...props
}: ButtonRootProps) => (
  <button
    ref={ref}
    {...props}
    type={type}
    data-ds-button=""
    data-variant={variant}
  />
);

export const Button = { Root };
```

Each component should have no visible styling—only resets and basic setup typical of headless components. Look, feel, and sizing should come from dedicated theme files that consumers import from `theme/<name>/<component-name>`.

The library must use Tailwind internally—for design tokens and related utilities—at the CSS layer only. It must not rely on Tailwind’s built-in colors, breakpoints, or fonts; it defines its own.

For now, implement all `parka` application components and port its branding to establish a generic design system with a default Parka theme. Additional themes will be added later.

The library must have 100% test coverage and end-to-end visual tests that confirm all component behavior in the documentation app.

It must support:

- `.claude/rules/accessibility.md`
- `Context API` via `react-kit` library utilities when needed

CSS must first define base design tokens, then use Tailwind together with those tokens to style each component.

Library structure:

```md
src
   button
      __tests__
      index.tsx
   style
      tokens.css
      index.css
      themes
         parka
            button.css
            other.css
```

The package must expose fully tree-shakable, modular imports.
