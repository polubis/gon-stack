# React API

Component author reads this page and knows the shape of a component API, when it is simple, when it is compound, how props and refs behave.

## Terms

- **[namespace_export]** - one exported object per component holding its parts. e.g. `Button = { Root }`
- **[root]** - part named `Root`. Renders the root element. Owns context in a [compound_component].
- **[part]** - any member of a [namespace_export]. e.g. `Select.Option`
- **[simple_component]** - component with one [part], `Root` only. e.g. `Button`
- **[compound_component]** - component with several [part]s sharing state through [root_context]. e.g. `Select`, `Modal`, `Layout`
- **[root_context]** - React context created and provided by [root], read by sibling [part]s
- **[native_props]** - props of the DOM element a [part] renders. e.g. `ComponentProps<'button'>`

## Requirements

### Shape

- **SHP-1** MUST export every component as a [namespace_export]. `<pattern:export const {Component} = { Root, ...parts }>`
  - 1A. [simple_component] exports `{ Root }` only. Usage: `<Button.Root />`.
  - 1B. Same shape for simple and compound. A [simple_component] grows into a [compound_component] without a breaking change.
- **SHP-2** MUST keep [simple_component] free of context and sub-parts. No [compound_component] where one element does the job.
- **SHP-3** MUST use [compound_component] when parts share state or must be arranged by consumer. `<examples:Select, Modal, Layout>`
  - 3A. Test: if consumer needs to reorder, omit, or wrap inner pieces, it is compound.
  - 3B. Test: if configuration is a prop list, it is simple.
- **SHP-4** MUST NOT mix both styles in one component. Either one [root] or [root] plus [part]s, never props that duplicate a part.
- **SHP-5** MUST use named exports only. No default export, no barrel with side effects.

### Root and context

- **CTX-1** MUST create [root_context] with `context` from `@repo/react-kit/context`. No raw `createContext`. One context per [compound_component].
  - 1A. Call shape: `const [Provider, useContext] = context('Select', useSelect)`. Name is PascalCase, without `Provider` or `Context` suffix.
  - 1B. Second argument is a hook holding state and actions. Its return value is the context value. Its single argument is the `value` prop of `Provider`.
  - 1C. [root] renders `Provider` and passes its own props as `value`.
  - 1D. Lives in the component's own file, e.g. `select/context.ts`.
- **CTX-2** MUST NOT hand-write the missing-provider check. `useContext` from `context` throws when [part] is outside [root]. Verify: `<Select.Option />` alone fails with `useSelectContext must be used within a SelectProvider.`
- **CTX-3** MUST keep context value small and stable. State and actions the parts need, nothing else.
  - 3A. Split into state context and actions context when actions never change and state does.
- **CTX-4** MUST NOT export `Provider`, `useContext`, or the raw `Context` from the package entry. Parts reach it internally only.
- **CTX-5** MUST let [root] be controlled or uncontrolled for any state it owns. `<props:value, defaultValue, onValueChange>`
  - 5A. Naming is the same in every component: `{name}`, `default{Name}`, `on{Name}Change`.

### Props

- **PRP-1** MUST extend [native_props] of the rendered element. `Omit` only where the component narrows a prop. e.g. `type` on button.
- **PRP-2** MUST spread remaining props onto the rendered element. Consumer `className`, `style`, `aria-*`, `data-*`, handlers all pass through.
- **PRP-3** MUST apply library attributes after the spread when they are not overridable. e.g. [root_hook], `type`.
- **PRP-4** MUST take `ref` as a normal prop. No `forwardRef`.
- **PRP-5** MUST expose each look choice as an optional prop with a default, mapped one-to-one to an [axis] data attribute. e.g. `variant` → `data-variant`.
  - 5A. Prop value union is exported as a type. e.g. `ButtonVariant`.
  - 5B. Default lives in destructuring, not in CSS.
- **PRP-6** MUST NOT add props that only restyle. Look is changed by token, class, or hook.
- **PRP-7** MUST NOT add boolean props that could be native attributes. e.g. `disabled`, not `isDisabled`.
- **PRP-8** SHOULD keep props flat and few. More than a handful signals a missing [part].

### Rendering

- **RND-1** MUST render one DOM element per [part] by default. No wrapper elements consumer cannot remove.
- **RND-2** MUST set [root_hook] on [root] and [part_hook] on every other [part].
- **RND-3** MUST NOT import CSS. Style is separate.
- **RND-4** MUST keep [part]s as plain function components. No class components, no HOCs, no `React.memo` by default.
- **RND-5** MUST work in server rendering. No access to `window` or `document` during render.

### Types

- **TYP-1** MUST export a props type per [part]. `<pattern:{Component}{Part}Props>` e.g. `ButtonRootProps`.
- **TYP-2** MUST export value unions used by props. e.g. `ButtonVariant`.
- **TYP-3** MUST NOT export implementation types. Only what consumer can pass or receive.
- **TYP-4** MUST infer from [native_props] instead of redeclaring. `ComponentProps<'button'>`, not a hand-written list.

## Example

Simple component:

```tsx
import type { ComponentProps } from 'react';

type ButtonVariant = 'primary' | 'secondary' | 'ghost' | 'danger';

type ButtonRootProps = Omit<ComponentProps<'button'>, 'type'> & {
  variant?: ButtonVariant;
  type?: 'button' | 'submit' | 'reset';
};

const Root = ({ variant = 'primary', type = 'button', ref, ...props }: ButtonRootProps) => (
  <button ref={ref} {...props} type={type} data-ds="button" data-variant={variant} />
);

export const Button = { Root };
export type { ButtonRootProps, ButtonVariant };
```

Compound component, context:

```ts
import { context } from '@repo/react-kit/context';

export const [Provider, useContext] = context('Select', useSelect);
```

Compound component, usage:

```tsx
<Select.Root value={v} onValueChange={setV}>
  <Select.Trigger />
  <Select.List>
    <Select.Option value="a">A</Select.Option>
  </Select.List>
</Select.Root>
```
