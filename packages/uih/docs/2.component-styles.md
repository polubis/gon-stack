# Component styles

Component author reads this page and knows where styles live, how a component is hooked, how it resolves values, how it can be overridden.

## Terms

- **[style_file]** - one plain `.css` file per component, next to its `.tsx`. e.g. `button/index.css`
- **[root_hook]** - attribute on component root, only selector entry. e.g. `data-ds="button"`
- **[part_hook]** - attribute on inner element. e.g. `data-ds-part="icon"`
- **[axis]** - one prop that changes look, exposed as data attribute. e.g. `data-appearance`, `data-color`, `data-size`
- **[color_role]** - value of `data-color`. Sets [role_channel] once in `ds.base`. e.g. `danger`
- **[role_channel]** - public pair `--ds-role`, `--ds-role-on`. Components read it, never read role name.
- **[exception]** - allowed rule break, marked `/* ds-exception: {reason} */`
- **[appearance]** - value of `data-appearance`. Decides how [role_channel] is painted. e.g. `solid`, `soft`, `outline`, `ghost`
- **[state_hook]** - native pseudo-class or ARIA attribute that drives state. e.g. `:disabled`, `[aria-busy]`
- **[semantic_token]** - shared intent token. e.g. `--ds-color-primary`
- **[component_token]** - per-component, per-property hook. e.g. `--ds-button-radius`
- **[private_token]** - helper inside one component. e.g. `--_h`
- **[derived_token]** - computed from another token via `color-mix`. e.g. hover
- **[fallback_default]** - default in `var()` second arg
- **[theme_scope]** - element with `data-ds-theme`

## Requirements

### Files

- **FIL-1** MUST keep exactly one [style_file] per component, next to component source. `<pattern:src/{component}/index.css>`
- **FIL-2** MUST write plain CSS. No CSS-in-JS, no preprocessor, no runtime style injection. Verify: file works when imported by any bundler or `<link>`.
- **FIL-3** MUST NOT import another component's [style_file]. Shared values come from [semantic_token].
- **FIL-4** MUST keep component logic in `.tsx`, never in CSS. TSX only sets [root_hook], [part_hook], [axis] attributes.

### Cascade

- **CAS-1** MUST declare layer order in every [style_file] first line. Repeat is safe, first declaration wins. `<order:ds.tokens, ds.base, ds.components>`
- **CAS-2** MUST put each component in its own sub-layer. `<layer:ds.components.{component}>`
- **CAS-3** MUST wrap every selector in `:where()`. `<specificity:0>` Verify: consumer one-class rule overrides any component rule, regardless of import order.
- **CAS-4** MUST NOT use `!important`, ids, element-only selectors, or class names. Classes belong to consumer.
- **CAS-5** MUST NOT depend on DOM nesting outside own root. Child combinators only between [root_hook] and own [part_hook].

### Hooks

- **HOK-1** MUST mark root with [root_hook] and nothing else for identification. `<pattern:data-ds="{component}">`
- **HOK-2** MUST mark inner elements with [part_hook]. `<pattern:data-ds-part="{part}">`
- **HOK-3** MUST expose each look choice as [axis] data attribute with enumerated values. `<attrs:data-appearance, data-color, data-size>`
  - 3A. Same axis name means same meaning in every component.
  - 3B. Axis value list is public API. Adding value is minor, removing is major.
- **HOK-4** MUST derive state from [state_hook], not from data attributes mirroring native state. e.g. `:disabled` not `data-disabled`.
  - 4A. Disabled MUST cover `:disabled` and `[aria-disabled='true']`.
  - 4B. Non-native state (open, selected, loading) uses `aria-*` first, `data-state` only when no ARIA fits.
### Variants

- **VAR-1** MUST split color from appearance. [color_role] picks hue, [appearance] picks paint. N roles × M appearances needs N + M rules, not N × M.
  - 1A. [color_role] rules live once in `ds.base`, not in components. Rule sets only [role_channel] from `--ds-color-{role}` and `--ds-color-on-{role}`.
  - 1B. Component [appearance] reads only [role_channel], never a role name. Verify: grep component file finds no `danger`, `primary`.
  - 1C. Default role is `primary` where it makes sense, `neutral` otherwise. Set on element, not by missing attribute.
- **VAR-2** MUST build bg, fg, border of each [appearance] from [role_channel] with [derived_token]. Copy to `--_c`, `--_on` on root if short name wanted. e.g. soft bg `color-mix(in oklab, var(--_c) 12%, transparent)`.
- **VAR-3** MUST compute hover, active, subtle from base via `color-mix`. Verify: adding role needs zero new hover rules.
- **VAR-4** SHOULD NOT add per-variant [component_token]. Component tokens are per property. `<pattern:--ds-{component}-{property}>` e.g. `--ds-button-radius`, not `--ds-button-primary-radius`.
  - 4A. Color override has one hook per paint property. `--ds-button-bg`, `--ds-button-fg`, `--ds-button-border-color`. Applies to every appearance.
- **VAR-5** MUST define size as [axis]. Each size sets private tokens (`--_h`, `--_px`, `--_fs`) from `calc(var(--ds-space) * n)` and type tokens.

### Token use

- **TOK-1** MUST resolve every value as `var(--ds-{component}-{prop}, var(--ds-{semantic}))`. Fallback is always semantic token, never literal.
  - 1A. Literal allowed only for structural values with no theme meaning. e.g. `0`, `100%`, `1`, `none`.
- **TOK-2** MUST NOT hardcode color, radius, duration, easing, z-index, shadow. Verify: [style_file] has no hex, `rgb()`, `ms`, `s` literals.
- **TOK-3** MUST assign [private_token] on the root, read them on root and parts. Free to rename.
- **TOK-4** MUST NOT write `@media (prefers-reduced-motion)` in component. Motion tokens go to `0s` once in `ds.tokens`. Verify: component transitions stop with no component rule.
- **TOK-5** MUST keep [component_token] list per component short. Add one only when a real consumer overrides that property.

### Behavior in CSS

- **BEH-1** MUST use logical properties. `inline-size`, `padding-inline`, `margin-block-start`. Verify: `dir="rtl"` works without extra rules.
- **BEH-2** MUST size in `rem`/`em`, never `px`, except 1px hairlines via a token.
- **BEH-3** MUST wrap hover in `@media (hover: hover)`. Touch shows no sticky hover.
- **BEH-4** MUST draw focus with `:focus-visible` using `--ds-color-focus`, never remove outline without replacement.
- **BEH-5** MUST keep interactive target at least `--ds-target-size`. Component grows, never hides the minimum.
- **BEH-6** MUST support `forced-colors: active` for border, focus, selected state. Verify: control stays visible in Windows high contrast.
- **BEH-7** SHOULD use `@container` for responsive component internals, `@media` only for user preferences.

### Overriding

- **OVR-1** MUST support override ladder, least to most invasive. Consumer picks lowest tier that works.
  - 1A. Theme: [semantic_token] on [theme_scope].
  - 1B. Component token: `--ds-{component}-{property}` on wrapper or element.
  - 1C. Hook selector: consumer CSS on [root_hook], [part_hook], [axis]. Wins by CAS-3.
  - 1D. `className`, `style`. Win last.
- **OVR-2** MUST treat [root_hook], [part_hook], [axis] names and values, [role_channel] as public API. `<stability:public-api>` Rename = major.
- **OVR-3** MUST let consumer add [color_role] with one rule. e.g. `[data-color='brand'] { --ds-role: #7c3aed; --ds-role-on: #fff; }` Verify: every component renders `brand` with no component change.
- **OVR-4** MUST let consumer add [appearance] with own rule reading [role_channel]. No library edit.
- **OVR-5** MUST allow eject: consumer copies [style_file], drops import. TSX keeps working because it only sets hooks (FIL-4).
- **OVR-6** MUST mark library-side break of any rule here with [exception]. Unmarked break is a defect.
- **OVR-7** MUST NOT require [private_token] for any override. Verify: every override above uses only public names.

## Skeleton

Every [style_file] follows this order.

```css
@layer ds.tokens, ds.base, ds.components;

@layer ds.components.button {
  /* 1. root: private tokens, layout, paint from private tokens */
  :where([data-ds='button']) { }

  /* 2. parts */
  :where([data-ds='button'] > [data-ds-part='icon']) { }

  /* 3. (color roles live in ds.base, not here) */

  /* 4. appearances: read --ds-role, --ds-role-on only */
  :where([data-ds='button'][data-appearance='soft']) { }

  /* 5. sizes: set --_h, --_px, --_fs only */
  :where([data-ds='button'][data-size='sm']) { }

  /* 6. states: hover, active, focus-visible, disabled, busy */
  @media (hover: hover) { }

  /* 7. forced-colors */
  @media (forced-colors: active) { }
}
```
