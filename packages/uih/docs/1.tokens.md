# Token hierarchy

Theme author reads this page and knows which token tier to change, how tiers resolve, which names are stable.

## Terms

- **[token]** - CSS var with `--ds-` prefix. e.g. `--ds-color-primary`
- **[primitive_token]** - raw value, no intent. e.g. `--ds-palette-blue-600`
- **[semantic_token]** - intent name shared by all components. e.g. `--ds-color-primary`
- **[component_token]** - optional per-component hook. e.g. `--ds-badge-bg`
- **[private_token]** - helper inside one component. e.g. `--_c`
- **[derived_token]** - computed from another token via `color-mix`. e.g. hover, subtle, border
- **[theme]** - set of [token] values on a [theme_scope]
- **[theme_scope]** - element with `data-ds-theme`. Subtree inherits.
- **[fallback_default]** - default in `var()` second arg. e.g. `var(--ds-badge-bg, var(--ds-color-primary))`

## Requirements

### Tiers

- **TIER-1** MUST expose three public tiers: [primitive_token], [semantic_token], [component_token]. `<prefix:--ds->`
  - 1A. [primitive_token] is optional. `<pattern:--ds-palette-{name}-{step}>`
  - 1B. [semantic_token] is the main theme surface. `<layer:ds.tokens>` `<specificity:0>`
  - 1C. [component_token] exists only for properties people override. `<pattern:--ds-{component}-{property}>`
- **TIER-2** MUST keep [private_token] internal, free to rename. `<prefix:--_>`
- **TIER-3** MUST NOT set [derived_token] by hand. Verify: theme sets one color, hover/subtle/border follow.

### Resolution

- **RES-1** MUST read tokens in order [component_token] → [semantic_token] → [primitive_token] or literal. e.g. `--ds-badge-radius` → `--ds-radius-full` → value
- **RES-2** MUST put component default in [fallback_default], never on the element. Verify: [component_token] set on wrapper still applies.
- **RES-3** MUST resolve priority low → high: [fallback_default], `:root`, [theme_scope], theme/consumer CSS, `className` and `style`.
- **RES-4** MUST let nearest [theme_scope] win. `<scope:[data-ds-theme]>`

### Naming

- **NAM-1** MUST name [semantic_token] by intent, not look. e.g. `--ds-color-primary`, not `--ds-blue`. `<stability:public-api>`
- **NAM-2** SHOULD list [component_token] names on each component page.

### Semantic groups

- **SEM-1** MUST cover color roles, color surfaces, type, shape, space, depth, motion.
  - 1A. Color roles: `primary`, `neutral`, `success`, `danger`, `warning`.
  - 1B. Color surfaces: `surface`, `on-surface`, `border`, `focus`.
  - 1C. Space is one base unit `--ds-space`; components use `calc(var(--ds-space) * n)`.
- **SEM-2** MUST treat dark mode as a [theme] swapping surface and color tokens, not a tier.

### Scale

- **SCL-1** MUST scale by device with one [semantic_token] `--ds-scale`, unitless, on `:root`. It is applied once, as root font size `calc(100% * var(--ds-scale))`. Components never branch on viewport. `<prefix:--ds->`
  - 1A. Everything in `rem` follows, so tokens stay plain `rem`. Hairline stays `rem` too. Never `px`.
  - 1B. Subtree density is a second token `--ds-density`, unitless, default `1`, multiplies `--ds-text-*` and `--ds-space`. It never touches root. Device scale and density never share a token, so nothing scales twice.
  - 1C. Tokens are computed where declared. A dense subtree MUST carry `data-ds-theme` so tokens are declared again there. e.g. `<div data-ds-theme style="--ds-density: 0.8">`.
- **SCL-2** MUST step `--ds-scale` and set root font size in the [theme] file `scale.css`, mobile first, `min-width` queries in `rem` at repo breakpoints. e.g. phone `0.875`, 480 `0.9375`, 768 `1`, 1280 `1.0625`, 1920 `1.125`.
  - 2A. Breakpoints without own step (640, 1024, 1440) inherit the step below.
- **SCL-3** MUST keep everything `rem`, never `vw` or `px`. Verify: browser default font size still scales the UI.
